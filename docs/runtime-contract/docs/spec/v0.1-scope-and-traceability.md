# v0.1 Scope and Traceability

> Parent specification: `../Agent_Meta_Runtime_Requirements_Design_v0.1.md` (v0.1-r11)
> Status: normative planning baseline; implementation status starts at `SPECIFIED` and may only move by evidence from the named test.  
> Scope rule: all rows marked `Required` block the Runtime v0.1 release. `External-Seed` blocks only the independently released Seed project and is never a Runtime release input. `Deferred-M5` and `Deferred-schema` require schema/API reservation but not executable succession.

## Verification rules

Harness consumer补充（2026-10-30）：[ADR 031](../adr/031-public-harness-consumer-contract.md)
发布Contract 1.1.0的纯打包API与内容验证规则。新增回归证明为
`tests/unit/test_public_package_contract.py`；这是Runtime package contract证明，
不替代External-Seed的AC-M17/AC-M48/NFR-M48，也不关闭RP-00～RP-02。

[ADR 032](../adr/032-public-host-spi.md)记录执行期SPI的版本边界；准备阶段证明为
`tests/unit/test_public_host_values.py`与`tests/unit/test_harness_package_loader.py`。
它们分别验证规范化值和显式AMPAK加载，不替代真实Task/Authority/恢复链路。

[ADR 033](../adr/033-local-command-authority-and-credential-storage.md)补充公开命令签名、
同事务授权/扣次与Windows DPAPI/owner-only DACL。回归为
`tests/unit/test_public_command_authority.py`、`tests/unit/test_windows_credentials.py`、
`tests/unit/test_bootstrap_init.py`与`tests/unit/test_operations_backup_gc.py`。
它们不关闭完整Host恢复、跨账户安全、Provider凭据或External-Seed发布门禁。

[ADR 034](../adr/034-signed-activation-plan-and-delegation.md)补齐签名激活计划、实际Composition
归属检查与同事务批量委派，回归为`tests/unit/test_activation_authority.py`。
该证明不替代Backend health、serving切换和独立消费者Host生命周期证明。

[ADR 035](../adr/035-local-daemon-lifecycle.md)增加Public API 1.1的实例绑定停止与真实daemon管理面；
回归为`tests/unit/test_daemon_lifecycle.py`和`tests/unit/test_daemon_process.py`。
未接入Host时serving readiness强制为false，不关闭RP-00～RP-02或外部Seed发布门禁。

[ADR 036](../adr/036-task-free-factories-and-async-reconciliation.md)固定无Task的factory/health准备，
并将同步/异步Reconciler复用为同一事务程序。回归为`tests/unit/test_async_reconciliation.py`
及AMPAK loader/Probe/Reconciler原有测试；实际Host实例、Task执行和恢复门禁仍待完成。

[ADR 037](../adr/037-bound-trusted-host-and-durable-invocation-journal.md)接通显式信任的进程内Host、
冻结接收View、Context登记与模型/PURE工具的持久调用日志。回归为`tests/unit/test_bound_harness.py`
及异步outbox取消测试。独立Seed已新增真实wheel/daemon AMPAK执行与进程kill恢复测试；
完整Context、强隔离、升级故障及S01A/S02矩阵仍未完成，所有需求状态保持原值。

[ADR 038](../adr/038-harness-source-audit-and-serving-recovery.md)补齐全包源码边界、provenance与
单包code归属检查，修复相对import lint漏报，并通过显式存储端口把Reconciler事务接到Service授权。
实际serving health与desired候选失败状态分开：坏版本不阻止旧版本继续执行；重启只重绑定已冻结
serving/Task快照，publisher trust丢失时明确终止不安全恢复。新增Runtime回归与独立Seed公开负向
套件不改变完整Context/Backend/External-Seed发布状态。

[ADR 039](../adr/039-frozen-context-policy-and-host-recomputation.md)增加冻结Context来源、
制品化策略/normalizer/tokenizer/renderer、20/30/20/15/15预算与先脱敏后排序，并由Host独立重算。
Runtime回归为`tests/unit/test_context_contract.py`及真实AMPAK的六类伪造投影拒绝测试；
独立Seed假Provider改为消费脱敏投影。完整外部Context/恢复矩阵与发布门禁仍未关闭。

[ADR 040](../adr/040-public-task-execution-inspection.md)在Public API 1.2新增只读Task.GetExecution，
公开有界的真实Invocation/Projection、冻结引用和预算元数据；它不增加Host权限或暴露原始内容。
回归包含真实AMPAK元数据查询、无写入、缺失/越Realm/bounds与旧minor拒绝，独立恢复门禁仍需实际证明。

[ADR 041](../adr/041-installation-reference-and-grant-generation-guards.md)将卸载引用检查限定到目标
installation的Composition/Capability版本归属，并补上State owner与UNKNOWN Effect等阻止项；
旧包drain后可卸载而不停止新包。生命周期撤销覆盖所有旧激活Grant，保留当前代，切换即撤销旧权限的
规则不变。Runtime归属/Grant回归及独立Seed升级测试不自动关闭RP-00/RP-07或发布状态。

[ADR 042](../adr/042-public-ordinary-artifact-content.md)在Public API 1.3增加有界普通Artifact内容读取。
服务与SDK分别核对size/hash，CAS读取最多声明大小加一；加密、已删除或crypto-erased分类不回退
到明文。回归为`tests/unit/test_artifact_content.py`与既有staging/SDK测试；它不提供Restricted读取，
也不关闭完整RP-04、State/Scratch或外部发布状态。

[ADR 043](../adr/043-strict-task-submission-scalars.md)修正Task接纳中的隐式预算/期限转换；SDK、CLI与
服务端复用严格标量校验，deadline 0保留为已过期时间，且CLI公开既有deadline字段。
`tests/unit/test_task_submission_scalars.py`覆盖签名坏输入无接纳/无staging；独立Host矩阵继续验证
过期、调用中deadline/cancel和已确认结果保护，不代表协作式profile具有硬抢占能力。

[ADR 044](../adr/044-public-ordinary-principals-and-delegation.md)在Public API 1.4增加普通公开身份
注册、严格委派与限定撤销。`tests/unit/test_public_principals.py`验证真实签名IPC、身份不可改、
多维衰减、完整scope、一次扣次、失败回滚、不可用金额上限和旧minor拒绝。独立消费者可用自有密钥
验证发起Actor与Harness Service分别授权；该增量不关闭完整RP-01/RP-05/RP-07或外部发布门禁。

[ADR 045](../adr/045-cooperative-host-call-scheduling.md)修复连续立即完成的Host调用阻塞管理面调度：
三个异步入口在事务之外让出事件循环，随后重新检查取消/期限与授权。
`tests/unit/test_host_cooperative_scheduling.py`及真实AMPAK/独立Context回归验证协作性，不代表硬抢占。

[ADR 046](../adr/046-public-task-state-trace.md)增加Public API 1.5的有界只读Task.GetTrace，
提供真实Action当前状态、按序Fact状态元数据和Task内causal edges。无原始payload或存储路径，
不补造历史状态，不取代完整Fact/Evidence API或External-Seed的具名验收。

[ADR 047](../adr/047-root-certified-service-execution-tokens.md)实现既定Root→Service证书及执行令牌
纯验证契约，绑定worker/session/作用域/预算/期限并限制nonce重放缓存。它不代表实际Backend已装配，
bootstrap证书、持久ack和独立AC-M17仍需各自实现及验证。

[ADR 048](../adr/048-inmemory-session-outcome-and-retention-contract.md)收紧现有InMemory adapter的
真实session、handle、Artifact outcome、幂等语义、ack/hash、有限retention与取消UNKNOWN语义。
无执行令牌verifier的实例明确为contract-test-only，不把这些Runtime测试计入外部AC-M17。

[ADR 049](../adr/049-bootstrap-public-service-certificate.md)在真实init同事务登记Root签名Service
公开证书与可GC追踪引用，提供只用Service key的scoped signer及公开链读取。它不增加Service Grant
权限，旧开发数据不隐式认证，证书过期/损坏拒绝执行；Backend/Host与持久ack门禁仍未关闭。

[ADR 050](../adr/050-inmemory-host-activity-and-durable-ack.md)增加显式选择的真实InMemory Host
调用链：Service token校验、实际handle绑定、Invocation终态与ack outbox同事务提交，以及会话丢失的
明确观测。Public API 1.6公开有界binding摘要与当前View profile；`tests/unit/test_memory_host.py`
覆盖真实调用/ack、丢响应重启、错误签名、取消与提交失败。独立AC-M17仍需最终wheel运行及发布证据，
不将EMULATED持久性或trusted Python声明为强隔离，也不改变本表发布状态。

- Every ID appears exactly once. CI parses the parent document and this table and fails on missing, duplicate, or unknown IDs.
- Owner slice的分步计划由`../plans/v0.1/README.md`索引；计划文档可以引用多个ID，但不得重新定义ID或改变本表Scope。
- A row may move from `SPECIFIED` to `IMPLEMENTED` only when its contract artifact exists and its named test passes in the required CI matrix.
- A row may move to `VERIFIED` only in a release manifest that records test result, platform, runtime version, schema/protocol versions, and evidence hash.
- Grouped tests may import shared fixtures, but the named test module must contain or reference an assertion tagged with the exact ID.
- Scope changes require an ADR and synchronized edits to the parent specification, this file, feature report, and release checklist.
