# Changelog

## 0.1.0.dev1 — unreleased

- Independent project and public-consumer architecture checks.
- Versioned Runtime contract inputs and evidence-based release gates.
- Public State management consumer and exact signed-command replay after owned daemon kill.
- Signed development tools package with Artifact/State adapters, deterministic JSON normalization (same content-addressed output ArtifactId for identical calls on a real daemon — including across a real State revision change in a fresh task), scoped grants, per-channel Scratch truncation marking, transcript-State refusal and controlled synthetic Provider integration.
- Consumer-side session coordinator and REPL front-end over the public message protocol: idempotent journal replay, pending-round recovery on attach, round lineage diagnostics and admission-refused rounds committed with their FAILED terminals.
- Release-lifecycle fault matrix: stale-plan refusal, envelope replay after owner restart, drained old-version serving, use-limited rollback re-minting and disjoint grant generations — drilled for the tools package too: an approved activation cuts serving over, an unhealthy candidate never realizes, the drained old version uninstalls terminally, and rollback is a fresh approved activation of the old version.
- Fail-closed model admission: a Provider profile that cannot state a firm pre-call maximum cost is refused before any wire request under a Task cost ceiling. The named SH-PROV-03 live-job module now gates explicit enablement and hard count/cost/timeout limits with missing-credential refusals that never report success.
- Provider recovery boundaries on real daemon processes: pre-send failure settles `NOT_SENT` with zero liability and is never resent; deadline or explicit cancel during an in-flight request settles the effect `UNKNOWN` with full liability, and a late upstream response cannot reverse the outcome. A profile declaring any durable-lookup retry policy other than `UNAVAILABLE_NO_RETRY` is refused when the package is built, and after a pre-send failure the returned endpoint serves only an explicitly submitted new Task (one authorized wire request, `CONFIRMED` settlement) while the settled `NOT_SENT` invocation is never resent. Credential containment: after a real model+tool run the secret value and derived hash appear on no public surface, and the public doctor scan reports zero findings.
- Fail-closed Evolution admission on a real daemon: unknown propose targets, unknown or malformed criteria artifacts, unregistered Worlds and unregistered candidates (including an ArtifactId in the CandidateId position) are refused with no object auto-created — serving refs and the public meta revision are identical after the whole refusal matrix — while a Proposal against the real serving composition is admitted with resolvable provenance and never moves serving. Conditional revisions are pinned: a Proposal conditioned on the caller's observed `expected_meta_revision` is admitted while a stale observation refuses `REVISION_CONFLICT` committing nothing, and `Evolution.Rollback` requires the `composition.rollback` permission and refuses fabricated parents and stale serving observations with the public meta revision and serving refs unchanged. The first Seed-side evidence collector leg reads real task history through public bounded traces into a canonical evidence fixture and resolves `source_evidence_ids` fail-closed before any Proposal: fact references must appear in the observed traces, artifact references must resolve through the public manifest, and empty/unknown/malformed evidence exits `InsufficientEvidence` committing nothing. The first S08 artifact-candidate governance leg builds `REPLACE_ARTIFACT` candidates fail-closed over the public Artifact store: candidates are bound to the SHA-256 of the live old value (stale expected hashes refused), kinds outside the tool-descriptor/skill-doc/prompt-policy whitelist are refused before anything is built, a candidate may not replace its own frozen evaluator, and the approval preview is a deterministic canonical hash/path diff. The bounded trigger policy aggregates failure modes from real task history through public bounded traces — empty history never triggers — and enforces one Proposal per window with a per-target-path cooldown that a fresh window cannot bypass, under a frozen ceiling that refuses wider policies.
- Product integration remains subject to the Runtime dependency ledger.
